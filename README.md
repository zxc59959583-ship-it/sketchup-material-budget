## 项目简介

在 SketchUp 方案推敲阶段，材质名称、构件尺寸和构造关系会频繁变化。传统做法通常需要人工读取面积，再到 Excel 中查找单价并汇总；一旦模型或材质发生变化，预算很容易失去同步。

材质实时预算把这条工作流放回 SketchUp：设计师用吸管选取需要计价的材质，插件递归读取群组与组件中的面，计算缩放后的真实面积，扣除共面接触和局部重叠区域，再与工作室价格库匹配，实时输出费用和剩余预算。对于不规范的 SU 材质名，v0.8.0 可以调用 DeepSeek 生成受价格库约束的候选，但必须经过人工确认才会参与计价。

## 核心能力

- **吸取即计价**：不要求逐个组件标注，只统计用户用 SU 吸管选中的材质。
- **真实面积**：递归处理群组、组件、嵌套实例和缩放变换。
- **避免重复计价**：同一 Face 正反面相同材质只计算一次。
- **重合面双边扣除**：两个实体局部接触时，交集面积从接触双方分别扣除。
- **工作室价格库**：支持 Excel、CSV，统一匹配标准编码、名称和别名。
- **费用拆分**：输出材料、人工、机械、管理费、利润和综合单价。
- **预算反馈**：显示当前成本、预算基准差额、项目总预算和剩余预算。
- **AI 辅助映射**：DeepSeek 只在当前价格库中推荐候选，不生成价格。
- **人工确认闭环**：确认结果双写当前模型和工作室词库，并合并读取、立即刷新预算。
- **大模型性能策略**：面积计算分阶段异步执行，带进度、空间剪枝和面积缓存。
- **完整导出**：输出 UTF-8 CSV，包含费用明细、预算指标和 AI 映射历史。

## 处理流程

```text
SU 吸管选取材质
        │
        ├─ 标准编码 / 名称 / 别名精确匹配
        │
        ├─ 未匹配材质：本地候选 → DeepSeek 重荐 → 人工确认
        │
        ├─ 映射写入当前模型 + 工作室词库
        │
        ├─ 递归扫描群组、组件与嵌套实例
        │
        ├─ 计算变换后的真实面积
        │
        ├─ 扣除同面重复与实体接触交集
        │
        ├─ 读取材料 / 人工 / 机械 / 管理 / 利润
        │
        └─ 输出当前成本、预算差额、剩余预算与 CSV
```

## 从第一代到第八代

项目不是一次性生成，而是围绕真实使用反馈逐代修正。这里的“八代”按能力阶段划分，部分阶段包含多个补丁版本。

| 代际 | 对应版本 | 当时的主要问题 | 关键改进 | 形成的能力 |
| --- | --- | --- | --- | --- |
| 第一代 | v0.1–v0.3 | 材质变化后预算不能稳定同步，出现 `nil.round` 错误 | 建立“面面积 × 单价”的实时面板，补齐空值与异常处理 | 基础预算闭环 |
| 第二代 | v0.4 | 同一面正反两侧使用相同材质时重复计价 | 每个 Face 只选择一个计价材质：正面优先，没有正面时读取背面 | 单面计价口径 |
| 第三代 | v0.5 | 只能识别完全包含，较小的局部重叠仍会漏算 | 三角剖分、二维投影、凸多边形裁剪；交集从双方分别扣除 | 任意共面局部交集 |
| 第四代 | v0.6–v0.6.1 | 逐一标注太慢，SU 吸管事件在部分版本不稳定 | 增加吸取材质白名单、模型内保存和当前材质轮询 | 吸取哪些就计算哪些 |
| 第五代 | v0.7.0 | 示例单价无法进入工作室真实工作流 | 接入 Excel/CSV；增加编码、名称、别名、费用组成、来源和预算基准 | 可追溯价格库 |
| 第六代 | v0.7.1–v0.7.1.1 | 每次启动都要重新选表，`WALL-002` 等编码不能稳定命中 | 固定关联与一键更新；编码、名称、别名统一规范化索引 | 稳定价格同步 |
| 第七代 | v0.7.2–v0.7.3 | 大模型等待时间长，修改价格也会重复扫描几何；只能看到已花金额 | 分批异步、空间剪枝、面积缓存、进度显示；增加总预算和剩余预算 | 性能可见与预算控制 |
| 第八代 | v0.8.0 | 非标准材质仍需人工查表；AI 结果与上方预算状态曾不同步；需要兼容旧版 SU | DeepSeek 受限候选、本地回退、人工确认、审计历史；映射双写与合并读取；移除 Ruby 2.7 和新版 JS 专属语法 | 可信 AI 标准化与 SU 2020+ 兼容 |

### 第一代：基础面积预算

最初目标非常小：材质变化以后，预算面板能同步变化。第一代完成材质面积、单价、小计和总预算的基本链路，并修复空数组或空值导致的 `nil.round` 计算失败。

### 第二代：解决正反面重复

SketchUp 的一个 Face 可以同时具有正面材质和背面材质。如果两面使用相同材质，预算不应该翻倍。第二代确定了“一个 Face 只形成一条计价记录”的口径。

### 第三代：从完全重合到局部相交

两个 5 ㎡面片如果局部接触 2 ㎡，净计价面积应为 `(5-2)+(5-2)=6 ㎡`。第三代引入三角剖分、共面筛选、二维投影和多边形裁剪，使小面积局部重叠也能被识别，并从接触双方各扣除一次。

### 第四代：吸管选材

人工逐个标注组件不适合方案阶段。第四代改成“吸取哪些材质，就计算哪些材质”，并将选择结果保存在 SKP 中。考虑到不同 SketchUp 版本的材质监听差异，同时采用事件监听和轻量轮询。

### 第五代：真实价格库

插件开始支持工作室 Excel/CSV 价格表，费用不再只有一个示例综合单价，而是拆分材料、人工、机械、管理费和利润，同时保留地区、日期和来源字段。

### 第六代：价格表持续同步

用户只需关联一次价格文件，后续更新 Excel 后点击“更新价格”即可。匹配索引覆盖标准编码、标准名称和别名，并忽略大小写、空格、下划线、连字符等差异。

### 第七代：性能与预算控制

面对数万计价面，计算拆分为扫描、重叠筛选、面积汇总和界面更新四个阶段。价格变化复用面积缓存，不重新扫描几何；同时加入项目总预算、剩余预算和超支提示。

### 第八代：可信 AI 与兼容性

DeepSeek 仅接收 SU 材质名和当前价格库候选编码，不接收模型几何或项目预算。模型最多返回 3 个候选、理由和置信度，程序再次校验编码，用户确认后才计价。确认映射同时写入当前 SKP 和工作室词库，当前模型优先，避免“下方已确认、上方仍待确认”。本代还以 SketchUp 2020 为最低版本，兼容 Ruby 2.5 和 CEF 64 基线。

## 安装与使用

1. 下载 [`su_material_budget_v0.8.0_SU2020_compatible.rbz`](./su_material_budget_v0.8.0_SU2020_compatible.rbz)。
2. 在 SketchUp 中打开“扩展程序管理器”，选择“安装扩展程序”。
3. 选择 RBZ，完成后重启 SketchUp。
4. 打开“材质实时预算”，关联工作室 Excel/CSV 价格表。
5. 保持插件窗口打开，用 SketchUp 吸管选取需要计价的材质。
6. 对未匹配材质检查候选并人工确认，然后查看预算变化。
7. 设置预算基准或项目总预算，最终导出完整预算 CSV。

## 系统要求

- SketchUp 2020 或更高版本。
- Windows 为当前主要验证平台。
- SketchUp 2020 使用 Ruby 2.5 与 CEF 64；仓库已提供静态兼容检查。
- DeepSeek 推荐为可选功能；不可用时仍可使用本地候选和确定性预算功能。
- Excel 导入依赖本机可用的 Excel/CSV 读取路径；CSV 可作为更稳定的跨环境格式。

## AI、安全与数据边界

- API Key 只保存在本次 SketchUp 运行内存中，不写入 SKP、价格表、词库或导出文件。
- DeepSeek 只获得材质名称和当前价格库中的候选元数据。
- AI 不计算面积、不生成价格、不修改价格库，也不能跳过人工确认。
- 几何计算、费用汇总和预算输出均由本地确定性程序完成。
- 工作室映射保留 AI 建议、人工选择、最终结果和确认时间，便于复核。


## 常见问题

### 为什么已经人工确认，下方历史有记录，上方仍显示“待人工确认”？

早期 v0.8.0 只把审计历史保存在模型中，而预算匹配主要读取工作室全局词库。当前修订版已改成双写：映射同时保存到当前 SKP 与工作室词库，读取时合并两者并以当前模型优先。重新安装本仓库 RBZ 后再确认，预算行应立即更新为“工作室映射”。

### 为什么两个接触面都要扣除交集？

两个 5 ㎡面片局部接触 2 ㎡时，这 2 ㎡对双方都不是外露饰面，因此净计价面积为 `(5-2)+(5-2)=6 ㎡`，不是 8 ㎡。

### 正面和背面使用同一种材质会计算两次吗？

不会。每个 Face 只选择一个计价材质；正面有材质时优先采用正面，否则读取背面。

### 一定要配置 DeepSeek 才能使用吗？

不需要。面积计算、价格匹配、预算和导出均可在本地运行。DeepSeek 只用于未匹配材质的候选推荐；网络或 API 不可用时会回退到本地候选。

### 为什么价格库中的金额不能直接用于正式结算？

仓库价格用于演示字段、匹配和费用汇总流程。地区、品牌、规格、施工条件和时间都会影响价格，正式项目必须替换为工作室审核后的当期数据。

## 技术栈

- 插件入口与业务逻辑：Ruby、SketchUp Ruby API。
- 用户界面：`UI::HtmlDialog`、HTML、CSS、JavaScript。
- 几何计算：`Face#area(transform)`、递归实例变换、三角剖分、二维投影与凸多边形裁剪。
- 本地数据：SketchUp `AttributeDictionary`、JSON、CSV。
- 价格接入：Excel/CSV 工作室价格库。
- AI 推荐：DeepSeek Chat Completions API，本地解释性候选作为回退。
- 验证工具：Node.js、Python `zipfile`。

## 已知边界

- 插件服务于方案阶段快速反馈，不替代正式工程量清单、施工图算量或造价审计。
- 示例价格仅用于演示数据结构和工作流，不能直接用于真实项目结算。
- 极复杂或非共面的空间碰撞不等同于共面饰面接触，当前重叠扣除主要面向共面表皮。
- 当前仓库尚未加入明确的开源许可证；在权利范围确认前，不应默认按 MIT、Apache-2.0 等许可使用。
